# Contributing to idea-to-blueprint

Thank you for your interest in improving this skill! Here's how to contribute effectively.

## Ways to Contribute

- **Report issues** — Found a gap in the interview flow, a missing template section, or an inconsistency? Open an issue.
- **Improve documentation** — Clearer wording, better examples, or additional edge cases are always welcome.
- **Add templates** — New document templates for specialized product types (games, APIs, browser extensions, etc.).
- **Enhance references** — Strengthen the interview playbook, orchestration rules, or quality bar criteria.
- **Fix bugs** — Correct logical errors in the workflow gates or specialist role definitions.

## Guidelines

1. **Open an issue first** for significant changes to discuss the approach before investing time.
2. **Keep the skill agent-agnostic** — don't add vendor-specific agent syntax to core files.
3. **Preserve the safety model** — planning must remain read-only by default.
4. **Use clear, specific language** — avoid vague marketing phrases like "seamless" or "enterprise-grade."
5. **Test with a real agent** — verify your changes work with at least one coding agent before submitting.

## Pull Request Process

1. Fork the repository and create a feature branch (`feat/your-feature`).
2. Make your changes with clear, atomic commits.
3. Update the README if your change affects the public interface or structure.
4. Submit a PR with a description of **what** changed and **why**.

## Code of Conduct

Be respectful, constructive, and inclusive. We're building a tool to help people think clearly about products — let's model that clarity in our collaboration.
